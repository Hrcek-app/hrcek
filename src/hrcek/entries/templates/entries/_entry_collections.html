{% load i18n %}{% comment %} An entry's collections on the list: "In:" and each collection holding it, then "+ Collection" to add it to another hand-picked one. in_collections.py answers htmx with this template alone, so the div is the whole of it, swapped as a unit (outerHTML). entries/list.html's own loop `{% include %}`s it inside div.entry-body with no `status`, so the page never carries a second live region or messages swap of its own. Rendered only when there is something to show or offer, so an entry-body with nothing else in it still renders genuinely empty; list.html asks the same question before including it, since even an empty include leaves this file's final newline behind. A hand-picked collection carries an × to take the entry out; one that follows a label stays a plain link, since only the label decides it. "+ Collection" is .js-only: without JavaScript the entry's edit form is the way to choose collections, and this one stays out of sight. So is the whole line while the entry is in nothing yet, since the pill is then all it holds, and a static_src/hrcek.css rule then takes an entry-body holding nothing else out of the card too. Its forms declare swap:none for 4xx/5xx, so a refused or failed request leaves the line as it was and js/htmx-errors.js says so.
